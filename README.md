## What is checked

| Service               | URL                              | Down when                                                                |
| --------------------- | -------------------------------- | ------------------------------------------------------------------------ |
| Website and dashboard | `https://hotcfg.run`             | The request fails, times out, or answers outside 2xx                     |
| API                   | `https://api.hotcfg.run/_health` | As above, or the body lacks `"status":"ok"` (the database didn't answer) |

## Changing things

- **Services, page text, navigation:** `.upptimerc.yml`. Pushing it re-runs setup.
- **Look:** `assets/hotcfg/` holds the hotcfg theme: `tokens.css` (the palette, dark and light, copied from hotcfg's `web/src/index.css`), `status.css` (layout and components) and `theme.js` (the theme toggle). `assets/` is copied to the site root, so `assets/fonts/…` is served at `/fonts/…`. Pushing a change under `assets/` rebuilds the site.
- **Workflows** in `.github/workflows` are generated by Upptime and overwritten by its weekly template update: change `.upptimerc.yml` instead.

The token the workflows use is the repository secret `GH_PAT`: a fine-grained token for this repository with read and write access to Actions, Contents, Issues and Workflows.
